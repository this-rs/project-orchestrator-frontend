# Internationalisation

The app speaks the same 13 languages as the website (`website/src/i18n/locales.ts`): `en` (source), `fr`, `es`, `pt` (pt-BR),
`de`, `zh` (Hans), `ja`, `ko`, `vi`, `ru`, `uk`, `hi`, `ar` (right-to-left). Codes and metadata are a copy of the site's:
keep them in step when a language is added.

## How it works

- `src/i18n/messages/<lang>/<ns>.ts`: one file per language and domain (`common`, `nav`…). English is bundled; the others are lazy chunks.
- A language is an overlay of English: a missing key falls back to English, key by key (`merge.ts`, same module as the site).
- `useT()` gives `t('nav.groups.plan', { name })`, `number()` and `date()`. Keys are typed against English: a typo does not compile.
  A key missing at runtime renders the key itself (visible, never a crash). Without a provider (component tests) everything reads in English.
- `I18nProvider` (in `main.tsx`) picks the language: explicit choice (`localStorage` `po.locale`), else the browser's, else English.
  It keeps the current language on screen until the requested one is loaded, and sets `<html lang dir>`: Arabic flips the layout.
- `LanguageSelect` (sidebar footer) is the picker; options show each language's own name.

## Adding or translating a domain

1. Write `messages/en/<ns>.ts` (`as const`), add it to `catalog.ts` (`EnglishMessages`, `NAMESPACES`).
2. Write `messages/<lang>/<ns>.ts` for each language: `satisfies Translation<'<ns>'>`.
3. `npm run check:i18n` (report) / `npm run check:i18n -- --strict`. The same check runs in `npm test`: a key absent from English,
   an empty text, a lost or added `{name}` marker, or a text left identical to English fails. A legitimate cognate or proper noun is
   listed in `identical-ok.json` (`ns.key` for all languages, `lang:ns.key` for one).

## Not translated

Product and protocol vocabulary stays as written in code and by the website's glossary: Project Orchestrator, MCP, Claude Code, tool
names and actions, statuses used as identifiers (`in_progress`…), paths, commands.

## Right-to-left

Use logical utilities (`border-e`, `ms-*`, `ps-*`, `text-start`) in new code rather than `border-r`, `ml-*`, `pl-*`, `text-left`.
Existing screens are converted as their domain is translated.

## Coverage

Translated: sidebar navigation (groups, concepts, workspaces), header labels, language picker. The rest of the app is still English and moves
over domain by domain (settings, chat, then pages).
